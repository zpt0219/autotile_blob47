## 1. 已确定的范围

将现有 Blob47 图集生成能力提取为全新的独立开发项目，并整理状态、界面、算法和浏览器能力的边界。

本次约束以用户最新决定为准：

- **新仓库从零开始。** 在目标目录初始化独立 Git 仓库，不导入原仓库提交历史、不使用历史过滤或子树拆分，也不继承原仓库 remote。
- **按新产品设计数据格式。** 不读取旧存储键，不迁移旧用户预设，不兼容旧配方 JSON、旧分享链接或旧导出协议。复用旧算法与素材不等于保留旧数据协议。
- **仅做本地独立项目。** 不接入网站，不更新首页、nginx、原仓库部署脚本或统一启动器，不运行部署，不维护旧网址。
- 本轮采用 React + TypeScript + Vite，参照 Portrait Studio 的职责分层和浏览器隔离方式。
- 保持现有 Blob47 生成能力和有效参数的图像效果；新数据结构可以重新设计。
- 原 `autotile_mixer/` 在新项目验收期间保留为参考。本轮不删除原应用；清理原仓库引用是单独任务。

## 2. 当前代码与重构重点

现有 `autotile_mixer` 已有独立 package、Vite 配置、单元测试和浏览器渲染算法。主要问题集中在约 2,000 行的 `src/App.tsx`：

- 配方被拆成几十个 `useState`，再由 `currentRecipe` 汇总、由 `applyRecipe` 逐字段回写。
- 配方状态、预设操作、自动保存、恢复弹窗、文件导入、分享、画布绘制和 Pointer Events 混在一个组件中。
- `exportSheet.ts` 同时负责纯元数据构造与 DOM、Canvas、下载操作。
- `renderSheet.ts` 已提供纯 RGBA 渲染入口，但主画布中仍有图集组装循环；辅助线开关也会触发图集重新生成。
- `noiseTargets` 和自定义噪点颜色影响最终像素，但目前不属于 `Recipe`，无法作为完整配方保存与复现。
- 自动保存异常被静默忽略；恢复确认与默认状态自动保存的顺序需要明确。

提取时同时整理工程配置：

- Vite 与 TypeScript 的 `@lib` 指向原仓库 `../libs`，但当前源码没有使用这个别名，应移除。
- `gen-corpus` 脚本指向缺失的 `tools/gen-corpus.ts`，应移除失效入口。只有确有测试需求时，再提供本项目内的生成工具。
- 文档部分陈述过时，应按实际代码整理。当前图集为 8 列 × 6 行、32px 图块，即 **256 × 192px**；47 种规范 mask 与 48 个布局槽位的区别按当前规则保留。
- 烘焙花纹数据随项目复制并提交，构建不依赖原仓库或缺失的外部生成步骤。

参考文件：

- [架构与代码审查指南](../../64px-portrait-studio/docs/CODE_REVIEW_GUIDE.md)
- [文档模型](../../64px-portrait-studio/src/model/document.ts)

采用以下原则：

1. 模型与算法不依赖 React、DOM、Canvas、`window` 或 `localStorage`。
2. 可保存的配方、编辑器会话和交互临时状态分别管理。
3. 应用服务依赖窄接口，由应用入口注入浏览器实现。
4. 导出先捕获数据快照，再进行 PNG 编码和打包。
5. 存储失败可见；恢复、自动保存和清理有明确生命周期。
6. 多次画布更新合并到同一帧；辅助线独立于素材生成。

React 负责组件与状态订阅，effect 清理负责生命周期。不照搬 Portrait Studio 的手写 DOM 面板基类、完整 ViewModel 或命令体系。本轮不新增撤销重做功能。

## 5. 状态与新数据格式

### 5.1 单一完整配方

以一个 `Recipe` 对象保存所有决定图集像素的参数，通过统一动作更新，并集中完成校验、范围约束和关联字段调整。

纳入配方的内容包括角色颜色、边缘形状、色阶、透明模式、噪点算法与目标区域、噪点自定义颜色、描边、材质、自定义色阶和所有相关种子。

派生色阶与渲染参数通过纯函数计算，不作为第二份可写状态。应用预设、导入文件和打开新分享链接采用一次性完整配方替换。

### 5.2 会话与偏好

- 会话：试铺地图、当前工具、缩放、网格、标记点、选中的预设。
- 偏好：语言和需要记住的视图设置，使用本项目命名空间。
- 临时交互：活动指针、上一绘制单元、弹窗、提示和导入导出进行状态。

试铺地图本轮仍是会话数据，不纳入图集配方或分享链接。

### 5.3 全新的格式

为新项目定义明确的格式标识与初始版本号，覆盖配方 JSON、预设库、自动保存、新分享链接和导出元数据。

存储键统一使用新命名空间，例如 `autotile_blob47.recipe.v1`、`autotile_blob47.presets.v1`、`autotile_blob47.preferences.v1`。不读取旧 `adna_blob47_*` 或共享 `adna_lang`。

只实现新格式的校验与往返读写。格式错误或版本不支持时返回可见错误，不尝试旧格式回退。新版本号为未来演进准备，不包含旧应用迁移逻辑。

## 6. 渲染、保存与导出

### 6.1 统一渲染

图集预览、预设缩略图、试铺与导出共享同一套配方解析及像素生成逻辑。

- 配方变化生成素材 RGBA。
- 试铺地图变化复用素材图块，只更新地图画面。
- 缩放、网格与标记点变化只影响显示和覆盖层。
- 图集导出使用无辅助线的像素数据。

保留 Pointer Events、pointer capture 和连续拖动栅格化，覆盖鼠标、触控笔、触摸及取消手势。

### 6.2 自动保存与恢复

自动保存服务接收注入的存储接口，集中管理防抖、待保存快照、取消与销毁。

启动时明确处理初始预设、新分享配方与本项目已有暂存的优先级。恢复确认结束前暂停自动保存，避免默认配方覆盖待恢复内容。存储受限或配额超限时向界面报告失败。

### 6.3 导入与导出

导入完整解析和校验成功后才替换当前配方；失败保持当前编辑状态。

导出捕获完整配方与其生成像素的快照，PNG、JSON 和 ZIP 使用同一个快照。导出期间用户继续编辑，不改变正在打包的内容。下载适配器统一处理 ObjectURL 回收和失败提示。
